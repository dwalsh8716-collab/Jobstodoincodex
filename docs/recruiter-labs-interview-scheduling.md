# Recruiter Labs Interview Scheduling

## Status

Staged architecture only.

This is not live WhatsApp automation. This is not live Google Calendar or Meet
automation. It is a safe, manual-first scheduling layer for the future Recruiter
Labs client pipeline.

This is technical implementation guidance, not legal advice.

## Staged Scheduling Architecture

Future workflow:

1. Client requests interview in the private portal.
2. David approves whether the candidate should be contacted.
3. Candidate availability is requested by WhatsApp, email or manual follow-up.
4. Availability is stored against the interview request.
5. Client availability is matched or requested.
6. David approves the final slot.
7. A calendar-ready draft is prepared.
8. David manually creates or checks the Google Calendar event.
9. Google Meet is generated by Google Calendar only after approval.
10. Candidate and client confirmations are sent through approved channels.
11. Reminders are sent only where approved.
12. All sensitive actions are audit logged.

Initial version is manual-assisted. It reduces admin. It does not remove
judgement.

## WhatsApp Flow

WhatsApp may be used only when:

- `FEATURE_WHATSAPP_INTERVIEW_SCHEDULING=true`
- `WHATSAPP_BUSINESS_ENABLED=true`
- required WhatsApp Business API server env vars are configured
- candidate has a valid mobile number
- candidate has selected WhatsApp or explicitly agreed to WhatsApp contact
- the message is operational interview logistics
- the template is approved where required
- David has approved the workflow

Allowed message types:

- interview availability check
- interview confirmation
- interview reminder
- interview reschedule
- interview location update

Blocked message types:

- rejection
- offer withdrawal
- sensitive feedback
- salary negotiation
- bad news
- bulk marketing

Raw WhatsApp message text must not be stored. Store template names, trigger,
status, safe metadata and provider IDs only.

## Google Calendar And Meet Flow

Stage 1: manual Google Calendar setup.

David creates the event himself. The system can show the details to copy.

Stage 2: calendar-ready event draft.

The helper can prepare:

- event title
- start and end time
- timezone
- location instruction
- concise calendar body
- reminder suggestions

It does not create an event.

Stage 3: scoped Google Calendar API.

Only after approval:

- use OAuth
- use least-privilege scopes
- store secrets in Railway only
- document who can access the calendar
- keep a manual fallback

Stage 4: automatic event and Meet creation.

Only after David approves the final slot and the Google launch gate passes.

Do not ask David for Google passwords. Do not hardcode Google secrets. Do not
commit OAuth credentials.

## Approval Gates

Before candidate contact:

- interview request exists
- client request is legitimate
- candidate contact is appropriate
- candidate contact preference is known
- candidate WhatsApp consent is clear if WhatsApp is used
- David approves contact

Before final slot:

- candidate availability is known
- client availability is known
- timezone is confirmed
- interview format is confirmed
- David approves the final slot

Before WhatsApp:

- WhatsApp Business API is configured
- template is approved
- candidate consent/preference is recorded
- message is operational
- manual fallback exists

Before Google Calendar/Meet:

- Google OAuth is approved
- scopes are documented
- calendar owner is agreed
- Meet generation is approved
- David approves event creation

Migration:

```txt

```

Adds status fields to:

- `recruiter_lab_interview_requests.scheduling_status`

- `recruiter_lab_interview_requests.david_final_slot_approved_at`

- `recruiter_lab_interview_events`

The model supports:

- availability slots
- timezone
- secure-link token hashes for future availability links
- calendar event status
- Google Calendar event ID
- Google Meet URL
- message channel/status
- provider message ID
- safe error summaries
- David/admin scheduling tasks

It does not store:

- raw WhatsApp message bodies
- Google OAuth secrets
- raw candidate CV content
- unnecessary client notes

- manual fallback required
